## What is a “string” in Zig?

Zig does **not** have a built-in `string` type. Text is just **bytes**, almost always UTF-8, viewed through pointers and slices.

A string literal has a precise type: a single-item pointer to a **null-terminated** array of bytes:

```zig test
const std = @import("std");

test "string literal type" {
    const greeting = "hello";
    // Type: *const [5:0]u8  — pointer to [5 bytes + sentinel 0]

    try std.testing.expectEqual(@as(usize, 5), greeting.len);
    try std.testing.expectEqualStrings("hello", greeting);
}
```

In everyday code you almost always **coerce** that to a slice:

```zig test
const std = @import("std");

test "string as slice" {
    const msg: []const u8 = "hello";
    try std.testing.expectEqual(@as(usize, 5), msg.len);
    try std.testing.expectEqual(@as(u8, 'h'), msg[0]);
}
```

| Type | Meaning | When you see it |
| --- | --- | --- |
| `*const [N:0]u8` | Pointer to fixed, null-terminated literal | Bare `"…"` literals |
| `[]const u8` | Read-only byte slice | Idiomatic “string” parameter |
| `[]u8` | Mutable byte slice | Buffers you write into |
| `[:0]const u8` | Null-terminated slice | C interop, some OS APIs |

::callout{type="tip"}
When writing functions that accept text, prefer `[]const u8`. Callers can pass string literals, slices of buffers, or substrings without extra allocation.
::

## UTF-8 source, UTF-8 strings

Zig source files are UTF-8. Bytes in string literals are stored as-is, so non-ASCII text works naturally:

```zig test
const std = @import("std");

test "unicode in strings" {
    const flash = "⚡ zig ⚡";
    try std.testing.expect(flash.len > 3); // length is in *bytes*, not code points
}
```

::callout{type="warning"}
`.len` on a string is the **byte** length, not the number of Unicode code points or grapheme clusters. Multi-byte characters (emoji, many non-Latin scripts) occupy more than one byte.
::

## Escape sequences

| Escape | Meaning |
| --- | --- |
| `\n` | Newline |
| `\r` | Carriage return |
| `\t` | Tab |
| `\\` | Backslash |
| `\'` | Single quote |
| `\"` | Double quote |
| `\xNN` | Single byte (hex) |
| `\u{NNNN}` | Unicode code point encoded as UTF-8 in the string |

```zig test
const std = @import("std");

test "escapes" {
    const line = "first\nsecond";
    const raw = "\xff\xfe"; // arbitrary bytes — not necessarily valid UTF-8
    const sparkle = "\u{2728}"; // ✨

    try std.testing.expect(std.mem.indexOfScalar(u8, line, '\n') != null);
    try std.testing.expectEqual(@as(usize, 2), raw.len);
    try std.testing.expect(sparkle.len > 0);
}
```

## Multiline strings

Zig has a convenient multiline string syntax using `\\` at the start of each line:

```zig test
const std = @import("std");

test "multiline string" {
    const poem =
        \\Roses are red,
        \\Violets are blue,
        \\Zig is explicit,
        \\And so should you.
    ;

    try std.testing.expect(std.mem.indexOf(u8, poem, "Zig is explicit") != null);
}
```

Each `\\` line contributes its contents plus a trailing newline (except as defined by the syntax rules). This is ideal for embedded SQL, HTML snippets, or expected test output.

## Character literals

Character literals use single quotes. Their type is `comptime_int` — the Unicode **code point** value — not a one-byte `char` type like in C:

```zig test
const std = @import("std");

test "character literals" {
    const letter = 'z';
    const newline = '\n';
    const hex = '\x65'; // 'e'
    const pile = '💯';

    try std.testing.expectEqual(@as(u8, 122), letter);
    try std.testing.expectEqual(@as(u8, 10), newline);
    try std.testing.expectEqual(@as(u8, 'e'), hex);
    try std.testing.expect(pile > 255); // needs more than u8
}
```

Because they are integers, character literals coerce into any integer type wide enough to hold them. For ASCII, `u8` is fine. For full Unicode scalar values, think `u21`.

::callout{type="info"}
There is no distinct `char` type. A “character” is just an integer code point, or one or more bytes in a UTF-8 sequence depending on context.
::

## Comparing and searching strings

Use `std.mem` for equality, searching, and slicing:

```zig test
const std = @import("std");
const mem = std.mem;

test "string operations" {
    const a: []const u8 = "hello";
    const b: []const u8 = "hello";
    const c: []const u8 = "world";

    try std.testing.expect(mem.eql(u8, a, b));
    try std.testing.expect(!mem.eql(u8, a, c));

    // Prefix / suffix
    try std.testing.expect(mem.startsWith(u8, "hello world", "hello"));
    try std.testing.expect(mem.endsWith(u8, "hello world", "world"));

    // Find a substring
    const idx = mem.indexOf(u8, "hello world", "lo");
    try std.testing.expectEqual(@as(?usize, 3), idx);
}
```

::callout{type="danger"}
Do **not** compare slices with `==`. That compares the slice headers (pointer + length), not the contents. Always use `std.mem.eql` (or a higher-level helper) for textual equality.
::

## Slicing text

Slices let you take views without copying:

```zig test
const std = @import("std");

test "slicing strings" {
    const full: []const u8 = "hello world";
    const hello = full[0..5];
    const world = full[6..];

    try std.testing.expectEqualStrings("hello", hello);
    try std.testing.expectEqualStrings("world", world);
}
```

The syntax `s[start..end]` is half-open: it includes `start` and excludes `end`. Omitting `end` (`s[start..]`) goes to the end of the slice.

## Formatting output

`std.fmt` and print helpers use format strings. `{s}` prints a string slice; `{d}` prints integers; `{any}` is a debug-friendly catch-all:

```zig run
const std = @import("std");

pub fn main() void {
    const name: []const u8 = "Zig";
    const year: u32 = 2026;
    std.debug.print("Hello, {s}! Welcome to {d}.\n", .{ name, year });
}
```

## Mental model

1. Strings are **bytes** (`u8`), usually UTF-8.
2. Literals are null-terminated arrays behind a const pointer.
3. APIs should take `[]const u8` unless they need the sentinel.
4. Length is in **bytes**.
5. Content comparison goes through `std.mem`, not `==`.
