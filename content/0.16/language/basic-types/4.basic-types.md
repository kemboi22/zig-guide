## Why types matter so much in Zig

Zig is statically typed and **unapologetically explicit**. Types are not just for the compiler — they document intent, encode invariants (signed vs unsigned, optional vs required), and enable powerful compile-time programming because **types are values**.

This page is your map of the primitive landscape. You have already met numbers, bools, and strings; here we place them in context with the special types that make Zig unique.

---

## Numeric and boolean primitives

| Type | Role |
| --- | --- |
| `i8`…`i128`, `u8`…`u128` | Fixed-width integers |
| `iN` / `uN` | Arbitrary-width integers (any `N`) |
| `isize` / `usize` | Pointer-sized integers (indices, sizes) |
| `f16` `f32` `f64` `f80` `f128` | IEEE floating-point |
| `bool` | `true` or `false` |

```zig test
const std = @import("std");

test "primitives in action" {
    const flags: u4 = 0b1010; // 4-bit unsigned
    const ok: bool = flags == 0b1010;
    try std.testing.expect(ok);
}
```

## Special types

These types do not store “data” in the everyday sense — they encode **control**, **absence**, or **metaprogramming** concepts.

### `void`

A zero-bit type with a single value: `{}`.

```zig test
const std = @import("std");

test "void" {
    const nothing: void = {};
    _ = nothing;

    // Functions that return nothing actually return void
    const F = *const fn () void;
    _ = F;
}
```

Use `void` for “no payload” — empty success in an error union (`!void`), callbacks that return nothing, and fields that exist only as markers.

### `noreturn`

The type of expressions that **never produce a value to the caller**: infinite loops that never break, `return` from a function, `break`, `continue`, `unreachable`, and functions that always panic or exit.

```zig
fn die() noreturn {
    @panic("goodbye");
}
```

`noreturn` helps the compiler understand control flow. A function typed `noreturn` is not allowed to return normally.

### `type`

In Zig, types are first-class **values of type `type`**. That is the foundation of generics and much of `comptime` programming:

```zig test
const std = @import("std");

test "types are values" {
    const T: type = i32;
    const value: T = 42;
    try std.testing.expectEqual(@as(i32, 42), value);

    // @TypeOf returns a type value
    try std.testing.expect(T == @TypeOf(value));
}
```

### `anyerror`

The supertype of all error sets. You will see `anyerror!T` (often written `!T`) on fallible functions that may return many different errors.

```zig test
const std = @import("std");

fn mightFail(fail: bool) anyerror!u32 {
    if (fail) return error.Oops;
    return 7;
}

test "anyerror" {
    try std.testing.expectEqual(@as(u32, 7), try mightFail(false));
    try std.testing.expectError(error.Oops, mightFail(true));
}
```

### `anyopaque`

A type-erased, unknown type — Zig's answer to C's `void *` when you need an opaque pointer. You typically hold `*anyopaque` or `*const anyopaque` and cast back once you know the real type.

### `comptime_int` and `comptime_float`

The types of numeric **literals**. They exist only at compile time, have large (effectively arbitrary) precision, and coerce into concrete runtime numeric types when used in a typed context.

```zig test
const std = @import("std");

test "comptime numbers" {
    const n = 99; // comptime_int
    const x: u64 = n; // coerced at compile time
    try std.testing.expectEqual(@as(u64, 99), x);
}
```

## Pointers, arrays, and slices (preview)

You will study these in depth later; for now, recognize the shapes:

| Syntax | Meaning |
| --- | --- |
| `[N]T` | Array of `N` elements of type `T` |
| `[N:s]T` | Array with sentinel value `s` |
| `[]T` | Slice (pointer + length) |
| `[]const T` | Read-only slice |
| `*T` | Single-item pointer |
| `*const T` | Read-only single-item pointer |
| `[*]T` | Many-item pointer (unknown length) |
| `[*:s]T` | Many-item pointer with sentinel |
| `[*c]T` | C-style pointer (nullable, relaxed rules) |

```zig test
const std = @import("std");

test "array and slice" {
    const xs = [_]i32{ 1, 2, 3 }; // length inferred: [3]i32
    const view: []const i32 = &xs;

    try std.testing.expectEqual(@as(usize, 3), view.len);
    try std.testing.expectEqual(@as(i32, 2), view[1]);
}
```

## Optionals and errors (preview)

| Syntax | Meaning |
| --- | --- |
| `?T` | Optional — either a `T` or `null` |
| `!T` / `E!T` | Error union — a `T` or an error |
| `error{…}` | Error set |

```zig test
const std = @import("std");

test "optional and error union" {
    const maybe: ?u8 = null;
    const some: ?u8 = 10;
    try std.testing.expect(maybe == null);
    try std.testing.expectEqual(@as(u8, 10), some.?);

    const ok: anyerror!i32 = 1;
    const bad: anyerror!i32 = error.Nope;
    try std.testing.expectEqual(@as(i32, 1), try ok);
    try std.testing.expectError(error.Nope, bad);
}
```

## C ABI types

When talking to C, sizes of `int`, `long`, and friends are platform-defined. Zig provides matching types so FFI stays correct:

| Zig type | Typical role |
| --- | --- |
| `c_char` | C `char` (signedness is platform-dependent) |
| `c_short` / `c_ushort` | C `short` |
| `c_int` / `c_uint` | C `int` |
| `c_long` / `c_ulong` | C `long` |
| `c_longlong` / `c_ulonglong` | C `long long` |
| `c_longdouble` | C `long double` |

::callout{type="tip"}
For pure Zig code, prefer `i32`, `u64`, `usize`, and friends. Reach for `c_*` types at the boundary with C libraries and system headers.
::

## Primitive values cheat sheet

| Value | Type | Meaning |
| --- | --- | --- |
| `true` / `false` | `bool` | Booleans |
| `null` | `?T` | Empty optional |
| `undefined` | any | Uninitialized (unsafe to read) |
| `{}` | `void` | The void value |
| `unreachable` | `noreturn` | “This code must never run” |

```zig test
const std = @import("std");

test "unreachable in exhaustiveness" {
    const x: u1 = 1;
    const label = switch (x) {
        0 => "zero",
        1 => "one",
        // no else needed for u1 if both values covered
    };
    try std.testing.expectEqualStrings("one", label);
}
```

## How to choose a type

1. **Numbers:** pick the smallest width that is safe; use `usize` for sizes and indices.
2. **Text:** `[]const u8` for parameters; buffers as `[]u8`.
3. **Absence:** `?T`, not magic sentinel values (when you can avoid them).
4. **Failure:** `!T` / error sets, not out-parameters of mixed meaning.
5. **C boundaries:** `c_*` types and `extern` layouts.
6. **Generics:** take `comptime T: type` and build new types as values.
