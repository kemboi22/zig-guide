## Two ways types change

Zig draws a hard line between:

1. **Coercion** — implicit, only when the conversion is always safe (or proven safe at compile time).
2. **Casting** — explicit builtins (`@intCast`, `@floatCast`, …) when you accept a possible runtime check or information loss.

That design keeps “silent truncation” out of everyday code. If something might not fit, you write a cast on purpose.

---

## Coercion (implicit)

These happen automatically when the destination can represent every value of the source (or the compiler proves this particular value fits):

| From | To | Why it is allowed |
| --- | --- | --- |
| Smaller unsigned int | Larger unsigned int | `u8` → `u16` → `u32` → … |
| Smaller signed int | Larger signed int | `i8` → `i16` → … |
| Smaller float | Larger float | `f16` → `f32` → `f64` → `f128` |
| `comptime_int` | Any integer that fits the value | Known at compile time |
| `comptime_float` | Any float type | Known at compile time |
| Arrays → slices / pointers | Compatible views | Same elements, different shape |
| String literals | `[]const u8`, `[*:0]const u8`, … | Common coercions |

```zig test
const std = @import("std");

test "safe coercion" {
    const small: u8 = 100;
    const wide: u64 = small; // OK

    const half: f16 = 1.5;
    const full: f64 = half; // OK

    const literal: u32 = 1_000; // comptime_int → u32
    try std.testing.expectEqual(@as(u64, 100), wide);
    try std.testing.expect(full == 1.5);
    try std.testing.expectEqual(@as(u32, 1000), literal);
}
```

What does **not** coerce:

- Narrowing integers (`u32` → `u8`) — use `@intCast` or `@truncate`
- Float → int or int → float at runtime — use `@intFromFloat` / `@floatFromInt`
- Signed ↔ unsigned of the same width — use `@intCast` (checked) when needed
- Unrelated pointers — use `@ptrCast` carefully

```zig
const x: u32 = 300;
// const y: u8 = x; // compile error — may not fit
const y: u8 = @intCast(x); // explicit; illegal if x > 255 at runtime
```

## `@as` — name the destination type

`@as(T, value)` forces a coercion to `T`. It is not a “bit cast”; it only works when coercion is legal:

```zig test
const std = @import("std");

test "@as" {
    const x = @as(u32, 42);
    const y = @as(f64, 3);
    try std.testing.expectEqual(@as(u32, 42), x);
    try std.testing.expectEqual(@as(f64, 3), y);
}
```

You will use `@as` constantly to pin literal types and to help peer type resolution in branches.

## Integer casts

### `@intCast`

Converts between integer types when the **value** must fit the destination. In safety builds, out-of-range values are illegal behaviour (typically a panic).

```zig test
const std = @import("std");

test "@intCast" {
    const wide: u64 = 255;
    const narrow: u8 = @intCast(wide);
    try std.testing.expectEqual(@as(u8, 255), narrow);

    // Type can also be written on the left:
    const also: u16 = @intCast(wide);
    try std.testing.expectEqual(@as(u16, 255), also);
}
```

### `@truncate`

Keeps the low bits and **discards** the high bits — no range check. Use when wrap-style truncation is intentional (masks, hashing, protocol fields).

```zig test
const std = @import("std");

test "@truncate" {
    const wide: u32 = 0x12345678;
    const low: u8 = @truncate(wide);
    try std.testing.expectEqual(@as(u8, 0x78), low);
}
```

| Builtin | On overflow / out of range |
| --- | --- |
| `@intCast` | Illegal behaviour (checked in safe modes) |
| `@truncate` | Silent low-bit keep |

## Float ↔ integer

### `@floatFromInt`

Integer → float. Always defined; very large integers may lose precision in the float mantissa.

```zig test
const std = @import("std");

test "@floatFromInt" {
    const count: u32 = 42;
    const as_float: f64 = @floatFromInt(count);
    try std.testing.expectEqual(@as(f64, 42), as_float);
}
```

### `@intFromFloat`

Float → integer, **truncating toward zero**. Overflow or NaN is illegal behaviour.

```zig test
const std = @import("std");

test "@intFromFloat" {
    const pi: f64 = 3.14159;
    const truncated: i32 = @intFromFloat(pi); // 3
    const neg: i32 = @intFromFloat(@as(f64, -2.9)); // -2
    try std.testing.expectEqual(@as(i32, 3), truncated);
    try std.testing.expectEqual(@as(i32, -2), neg);
}
```

### `@floatCast`

Narrows (or converts between) float types. May lose precision.

```zig test
const std = @import("std");

test "@floatCast" {
    const precise: f64 = 3.141592653589793;
    const approx: f32 = @floatCast(precise);
    try std.testing.expect(@abs(approx - 3.1415927) < 0.0001);
}
```

## Other useful casts (overview)

You will meet these as you go deeper:

| Builtin | Role |
| --- | --- |
| `@ptrCast` | Reinterpret a pointer's type |
| `@alignCast` | Assert a higher alignment |
| `@constCast` | Remove `const` (use sparingly) |
| `@volatileCast` | Adjust volatile |
| `@bitCast` | Reinterpret bits as another type of the same size |
| `@enumFromInt` / `@intFromEnum` | Enum ↔ integer |
| `@errorFromInt` / `@intFromError` | Error ↔ integer |
| `@ptrFromInt` / `@intFromPtr` | Pointer ↔ address |

::callout{type="danger"}
`@ptrCast`, `@bitCast`, and `@constCast` can undermine type safety. Prefer higher-level APIs. When you must use them, keep the unsafe region small and document the invariant you are relying on.
::

## Peer type resolution

When two types meet — both branches of an `if`, arms of a `switch`, operands of an operator — Zig looks for a **common type**.

```zig test
const std = @import("std");

test "peer types with @as" {
    const flag = true;
    const val = if (flag) @as(u32, 1) else @as(u32, 2);
    try std.testing.expectEqual(@as(u32, 1), val);
}
```

If the peers cannot agree, you get a compile error:

```zig
// error: incompatible types
// const val = if (flag) @as(u32, 1) else @as(i32, -1);
```

Fix it by making both sides the same type (or a type that both coerce to):

```zig test
const std = @import("std");

test "reconcile peers" {
    const flag = false;
    const val: i64 = if (flag) 1 else -1; // both coerce to i64
    try std.testing.expectEqual(@as(i64, -1), val);
}
```

Numeric operators also peer-resolve. Mixing `u8` and `u16` typically promotes toward a common integer type according to Zig's rules — when unsure, annotate.

## A practical decision guide

| Goal | Tool |
| --- | --- |
| Widen a number safely | Coercion or `@as` |
| Narrow an integer, must fit | `@intCast` |
| Keep low bits only | `@truncate` |
| Int → float | `@floatFromInt` |
| Float → int | `@intFromFloat` |
| Smaller float | `@floatCast` |
| Pin a literal's type | `@as(T, literal)` |
| Unify `if` / `switch` branches | Same type or `@as` on both sides |

```zig test
const std = @import("std");

test "end-to-end conversions" {
    const raw: u64 = 200;
    const byte: u8 = @intCast(raw);
    const ratio: f64 = @as(f64, @floatFromInt(byte)) / 255.0;
    const percent: u8 = @intFromFloat(ratio * 100.0);

    try std.testing.expectEqual(@as(u8, 200), byte);
    try std.testing.expect(percent > 70 and percent < 90);
}
```
