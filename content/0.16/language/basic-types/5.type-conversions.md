## Coercion (Implicit)

Zig allows implicit coercion between types that are guaranteed safe:

- Integers coerce to larger integer types: `u8` -> `u16` -> `u32` -> `u64` -> `u128`
- Floats coerce to larger float types: `f16` -> `f32` -> `f64` -> `f128`
- `comptime_int` coerces to any integer type that can hold its value
- `comptime_float` coerces to any float type
- Small integers coerce to floats when no precision is lost (e.g. `u24` -> `f32`)

```zig
const x: u8 = 100;
const y: u64 = x;  // OK: u8 coerce to u64

const a: f16 = 3.14;
const b: f64 = a;  // OK: f16 coerce to f64
```

## Explicit Casts (Builtins)

All cast builtins take a single argument and return the source type. Use `@as` or type annotation to coerce to the destination type.

### `@intCast`

Narrows or widens an integer value at runtime:

```zig
const wide: u64 = 255;
const narrow = @as(u8, @intCast(wide));
// Or with type annotation:
const narrow: u8 = @intCast(wide);
```

Illegal behaviour if the value doesn't fit in the destination type.

### `@floatCast`

Narrows a float to a smaller float type:

```zig
const precise: f64 = 3.141592653589793;
const approx: f32 = @floatCast(precise);
```

### `@floatFromInt`

Converts an integer to a float:

```zig
const count: u32 = 42;
const as_float: f64 = @floatFromInt(count);
```

Always safe — no precision loss for values within range.

### `@intFromFloat`

Converts a float to an integer (truncates toward zero):

```zig
const pi: f64 = 3.14159;
const truncated: i32 = @intFromFloat(pi); // 3
```

Illegal behaviour if the value overflows or is NaN.

### `@as`

Performs a safe coercion (not a true cast — works only when coercion is valid):

```zig
const x = @as(u32, 42);
```

### `@truncate`

Reinterprets the bits of an integer, discarding high bits:

```zig
const wide: u32 = 0x12345678;
const low: u8 = @truncate(wide); // 0x78
```

## Peer Type Resolution

When multiple types meet in an expression (e.g. `if` branches), Zig finds a common type:

```zig
const x = if (condition) @as(u32, 1) else @as(u32, 2);
```

Both branches must resolve to the same type, or Zig will use peer type resolution to find a compatible type.
