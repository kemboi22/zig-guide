## Decisions with `if`

Zig's `if` is deliberately strict: the condition must be a **`bool`**. There is no truthy/falsy world where `0`, `null`, or empty strings silently count as false.

```zig test
const std = @import("std");

test "basic if" {
    const temperature: i32 = 22;
    var label: []const u8 = "cold";

    if (temperature > 20) {
        label = "warm";
    }

    try std.testing.expectEqualStrings("warm", label);
}
```

### `else` and chains

```zig test
const std = @import("std");

test "if else chain" {
    const score: u32 = 76;
    const grade: []const u8 = if (score >= 90)
        "A"
    else if (score >= 80)
        "B"
    else if (score >= 70)
        "C"
    else
        "needs work";

    try std.testing.expectEqualStrings("C", grade);
}
```

## `if` is an expression

Every `if` can produce a value. Both branches must agree on a type (via peer type resolution):

```zig test
const std = @import("std");

test "if as expression" {
    const a: u32 = 5;
    const result = if (a > 3) "big" else "small";
    try std.testing.expectEqualStrings("big", result);

    // Useful in assignments and returns:
    var x: u16 = 0;
    x += if (a > 3) 1 else 2;
    try std.testing.expectEqual(@as(u16, 1), x);
}
```

::callout{type="info"}
Zig has **no** ternary operator (`cond ? a : b`). Use `if (cond) a else b` — it is the same idea, with clearer syntax for multi-line bodies.
::

When the `if` is used as a statement (result discarded), `else` is optional. When it is used as an **expression** that must produce a value, you need an `else` (unless a branch is `noreturn`, e.g. `return` / `unreachable`).

## Optional capture

Optionals (`?T`) are either a value or `null`. `if` can **unwrap** them safely:

```zig test
const std = @import("std");

test "optional capture" {
    const maybe: ?u32 = 42;

    if (maybe) |value| {
        // value is u32 — only runs when maybe is non-null
        try std.testing.expectEqual(@as(u32, 42), value);
    } else {
        // maybe was null
        unreachable;
    }
}
```

The `|value|` syntax is a **capture**. It introduces a new name bound to the payload for the duration of that branch.

```zig test
const std = @import("std");

test "optional null branch" {
    const empty: ?[]const u8 = null;
    var message: []const u8 = "has value";

    if (empty) |text| {
        message = text;
    } else {
        message = "missing";
    }

    try std.testing.expectEqualStrings("missing", message);
}
```

::callout{type="tip"}
Prefer `if (opt) |v| … else …` over `opt.?` when null is a normal case. The `?` force-unwrap is for situations where null would be a bug.
::

## Error union capture

Error unions (`!T` or `E!T`) carry either a success payload or an error. `if` can split them:

```zig test
const std = @import("std");

fn mightFail(flag: bool) !u32 {
    if (flag) return 42;
    return error.Failed;
}

test "error union capture" {
    if (mightFail(true)) |value| {
        try std.testing.expectEqual(@as(u32, 42), value);
    } else |_| {
        unreachable;
    }

    if (mightFail(false)) |value| {
        _ = value;
        unreachable;
    } else |err| {
        try std.testing.expect(err == error.Failed);
    }
}
```

| Capture form | Payload branch | Failure branch |
| --- | --- | --- |
| Optional `?T` | `|value|` | `else` (no payload) |
| Error union `!T` | `|value|` | `else \|err\|` |

## Pointer capture

Prefix the capture name with `*` to bind a **pointer** to the payload — useful when you need to mutate it in place:

```zig test
const std = @import("std");

test "pointer capture" {
    var val: ?u32 = 42;

    if (val) |*ptr| {
        ptr.* += 1;
    }

    try std.testing.expectEqual(@as(u32, 43), val.?);
}
```

This works for optionals holding mutable data and for error unions when the success payload is mutable storage you want to update.

## Combining ideas

```zig test
const std = @import("std");

fn parsePositive(text: []const u8) !u32 {
    const n = try std.fmt.parseInt(u32, text, 10);
    if (n == 0) return error.NotPositive;
    return n;
}

test "if with real parsing" {
    const input: []const u8 = "17";

    const label = if (parsePositive(input)) |n|
        if (n > 10) "large" else "small"
    else |_|
        "invalid";

    try std.testing.expectEqualStrings("large", label);
}
```

## Common mistakes

1. **Non-bool condition** — write `if (ptr != null)` or capture; do not write `if (ptr)`.
2. **Missing `else` on expression `if`** — both value-producing branches required.
3. **Using `==` on slices for strings** — compare with `std.mem.eql`, then branch on the `bool`.
4. **Forgetting capture scope** — `|value|` only exists inside its branch.

if (condition) { … } else { … }
