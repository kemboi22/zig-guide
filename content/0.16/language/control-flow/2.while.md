## Loop while a condition holds

`while` repeats a body as long as a **`bool`** condition is true:

```zig test
const std = @import("std");

test "basic while" {
    var i: u32 = 0;
    while (i < 5) {
        i += 1;
    }
    try std.testing.expectEqual(@as(u32, 5), i);
}
```

Use `break` to leave early and `continue` to skip to the next iteration.

## Continue expressions

Zig's distinctive loop feature: a **continue expression** after `:` runs at the end of every iteration — including after `continue`:

```zig test
const std = @import("std");

test "while with continue expression" {
    var i: u32 = 0;
    var sum: u32 = 0;

    while (i < 5) : (i += 1) {
        if (i == 2) continue; // still runs i += 1
        sum += i;
    }

    // i takes 0,1,2,3,4 → sum = 0+1+3+4 = 8
    try std.testing.expectEqual(@as(u32, 8), sum);
}
```

This keeps increment logic out of the body and out of every `continue` path — fewer off-by-one bugs.

```zig
while (condition) : (continue_expr) {
    // body
}
```

The continue expression can be a block if you need multiple statements:

```zig test
const std = @import("std");

test "block continue expression" {
    var i: u32 = 0;
    var steps: u32 = 0;

    while (i < 3) : ({
        i += 1;
        steps += 1;
    }) {
        // empty body — work is in the continue expr
    }

    try std.testing.expectEqual(@as(u32, 3), i);
    try std.testing.expectEqual(@as(u32, 3), steps);
}
```

## Optional capture — drain until `null`

`while` can unwrap an optional each iteration and stop when the result is `null`:

```zig test
const std = @import("std");

fn next(comptime T: type, arr: []const T, idx: *usize) ?T {
    if (idx.* >= arr.len) return null;
    defer idx.* += 1;
    return arr[idx.*];
}

test "while optional capture" {
    const items = [_]u32{ 1, 2, 3 };
    var idx: usize = 0;
    var sum: u32 = 0;

    while (next(u32, &items, &idx)) |val| {
        sum += val;
    }

    try std.testing.expectEqual(@as(u32, 6), sum);
}
```

This pattern shines for iterators, read loops, and “poll until empty” APIs.

## Error union capture

With error unions, the loop continues on success and routes errors to `else`:

```zig test
const std = @import("std");

fn poll(ready: *bool) !u32 {
    if (ready.*) return 42;
    ready.* = true;
    return error.NotReady;
}

test "while error union capture" {
    var ready = false;
    var total: u32 = 0;

    // First call errors, else runs, loop ends — classic shape.
    // For a loop that retries, structure differently.
    while (poll(&ready)) |val| {
        total += val;
    } else |_| {
        // exit path when an error is returned
    }

    // After one error exit, total is still 0; call again now that ready is true:
    if (poll(&ready)) |val| {
        total += val;
    } else |_| {}

    try std.testing.expectEqual(@as(u32, 42), total);
}
```

::callout{type="info"}
Think of `while (expr) |payload| … else |err| …` as: “keep going while `expr` succeeds; when it fails, handle `err` and stop.”
::

## `while` as an expression

Loops can yield a value: `break value` provides the result, and `else` runs when the loop ends **without** `break`:

```zig test
const std = @import("std");

test "while as expression" {
    var i: u32 = 0;

    const found = while (i < 10) : (i += 1) {
        if (i == 7) break true;
    } else false;

    try std.testing.expect(found);
}
```

```zig test
const std = @import("std");

test "while else when no break" {
    var i: u32 = 0;

    const found = while (i < 3) : (i += 1) {
        if (i == 99) break true;
    } else false;

    try std.testing.expect(!found);
}
```

This is a clean way to encode search: “break with the answer, else default.”

## Infinite loops

`while (true)` is the idiomatic infinite loop. Always ensure a `break`, `return`, or similar exit exists (unless you truly mean “run forever”):

```zig test
const std = @import("std");

test "infinite while with break" {
    var n: u32 = 1;
    while (true) {
        n *= 2;
        if (n >= 16) break;
    }
    try std.testing.expectEqual(@as(u32, 16), n);
}
```

## Inline while

`inline while` asks the compiler to **unroll** the loop at compile time. The condition and continue expression must be comptime-known:

```zig test
const std = @import("std");

test "inline while" {
    comptime var i: u32 = 0;
    var sum: u32 = 0;

    inline while (i < 4) : (i += 1) {
        sum += i;
    }

    // Effectively: sum += 0; sum += 1; sum += 2; sum += 3;
    try std.testing.expectEqual(@as(u32, 6), sum);
}
```

::callout{type="warning"}
Use `inline while` for metaprogramming and tiny fixed bounds — not for large runtime iteration counts. Unrolling a huge loop explodes code size.
::

## When to choose `while` vs `for`

| Prefer `while` | Prefer `for` |
| --- | --- |
| Condition-driven loops | Iterating arrays / slices / ranges |
| Iterator / optional drain | Element + index walks |
| Retry / poll loops | Fixed sequences |
| Classic counter with complex exit | Parallel iteration over multiple sequences |

## Quick reference

```zig
while (cond) { … }
while (cond) : (i += 1) { … }

while (optional_expr) |value| { … }
while (error_expr) |value| { … } else |err| { … }

const r = while (cond) : (i += 1) {
    if (done) break value;
} else fallback;

inline while (comptime_cond) : (i += 1) { … }
```
