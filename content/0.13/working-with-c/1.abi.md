# ABI

Zig targets the platform's C ABI directly, which means Zig functions can be called from C and vice versa without a binding layer.

```zig
export fn add(a: i32, b: i32) i32 {
    return a + b;
}
```

The `export` keyword makes a function use the C calling convention and gives it a stable, unmangled symbol name — callable from any language that links against C.

## Importing C headers

Zig can translate and import `.h` files directly:

```zig
const c = @cImport({
    @cInclude("stdio.h");
});

pub fn main() void {
    _ = c.printf("Hello from C stdio\n");
}
```

::callout{type="info"}
`@cImport` requires a libc to be available for the target. Zig bundles its own libc headers and implementations for many targets, so this typically works out of the box, even when cross-compiling.
::

::callout{type="danger"}
Translated C code retains C's footguns — null pointers, unchecked casts, and undefined behaviour from the original headers all carry over. Treat `@cImport`-ed APIs with the same care you would in C.
::
