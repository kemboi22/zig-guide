# Running Tests

Zig has a test runner built directly into the compiler — no external framework needed.

```zig
const std = @import("std");
const testing = std.testing;

fn add(a: i32, b: i32) i32 {
    return a + b;
}

test "add two numbers" {
    try testing.expectEqual(@as(i32, 5), add(2, 3));
}
```

Run all tests in a file with:

```bash
zig test main.zig
```

## Test blocks

A `test` block is a top-level declaration with a string label and a body. Test blocks are only compiled when running `zig test` — they add zero overhead to a normal build.

::callout{type="tip"}
Give tests descriptive string labels. They're printed when a test fails, and are often the only context you get from a CI log.
::

## Assertions

`std.testing` provides several helpers:

| Function | Behaviour |
|---|---|
| `expect(bool)` | Fails if the value is `false` |
| `expectEqual(expected, actual)` | Fails if values differ |
| `expectError(error, result)` | Fails if the expected error isn't returned |

::callout{type="danger"}
`expectEqual` requires both arguments to be the same type. Mismatched integer types (`i32` vs `usize`, for example) will fail to compile rather than fail at runtime — cast explicitly with `@as` when comparing literals.
::
